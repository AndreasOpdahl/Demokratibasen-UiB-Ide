# In-domain capability retention data

In-domain texts to be used for capability retention tasks *(before pruning of 9 examples, see below*):

* __C2: Text prediction__ (3050 examples)
* __C3: Prompt continuation__ (9650 examples - it is actually 9649)

The texts are sampled from publically available case presentations, case minutes, meeting agendas and meeting minutes published by Norwegian municipalities.

## Source

The capability-retention data are extracted from the `155452_text_summary_examples_{ultra_narrow,narrow,medium,broad}.jsonl` files. These files contain the full examples, in a format similar to the `155452_text_summary_examples{,_train,_val,_test}.jsonl` files in the parent folder. They are disjoint in terms of document ids, but are drawn from the same Demokratibasen corpus.

`capability-retention-corpus.{csv,ods}` contain metadata about numbers of texts of different types and their sizes.
(There are only 99 final broad examples for C3.)

## Organisation

The prepared files to use for capability retention are
`TASK_BAND_examples.jsonl`
where

* __TASK__ is either: _3060_c2_text_prediction or 9650_c3_prompt_continuation_
* __BAND__ is one of: _ultra_narow, narrow, medium, or broad_

Each JSON line has these fields:
(document) __id, task, band, stage, text__,
where

* __STAGE__ is one of: _regular, major, final_
* __TEXT__ is extracted from the source documents _input text_ and has a token-length appropriate for the BAND

Texts are drawn randomly from all parts of the source documents - beginning, middle and end - but they always start on a word boundary. C3 prompt-question texts also start at a paragraph boundary, or at least a sentence boundary.

## Use

The dataset supports two capability retention tasks at three stages:

* __regular__ is for every in-training validation step, for example every 100 or 500 training steps
* __major__ is also for in-training validation, but less frequent, for example every 10th in-training validation step. _A major step must also include all the regular examples_ (which must be loaded from separate files).
* __final__ is for final post-training evaluation. It does not use the regular and major examples.

To use a text, it must be tokenised and truncated to this number of tokens according to band:

* __ultra-narrow__: 192 tokens (for c3 prompt-questioning, use first 96 tokens as the prompt)
* __narrow__: 512 tokens (for c3 prompt-questioning, use first 256 tokens as the prompt)
* __medium__: 2048 tokens (for c3 prompt-questioning, use first 512 tokens as the prompt)
* __broad__: 8912 tokens (for c3 prompt-questioning, use first 1024 tokens as the prompt)

If the window size is < 8912 tokens for a target model, truncate the broad band to 4092 tokens for that model.

In some cases, depending on the target model's tokeniser, there may always not be enough tokens. The evaluation methods must be able to account for this.

## Generation

The `TASK_BAND_{id,examples}.jsonl` files were generated by the `prepare_capability_retention_examples.py` script, and validated by `analyse_capability_retention_examples.py`, which also wrote analysis results to file.

## Pruning

Pruning of all capability‑retention JSONL files is complete, using the same criteria as for the main dataset:

* non‑Norwegian input (input_lid not in {nob, nno} or missing)
* embedding distance > 0.6 (from 12709_capability_retention_embeddings.jsonl)
* input length < 50 tiktokens (on input if present, otherwise text)
* plus the four explicit dokument_ids.

Embedding distances were loaded for all 12,709 capability‑retention dokument_ids.
